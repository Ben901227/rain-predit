# 定量降水預報 · 指定地點

在中央氣象署的[定量降水預報圖](https://www.cwa.gov.tw/V8/C/P/QPF.html)上標出指定地點，
並直接讀出該點位的累積雨量。手機可用。

**<https://ben901227.github.io/rain-predit/>**

官方的預報圖只有全台範圍，看不出「我要去的那個點」落在哪一塊色階上。
這個網頁把地點標在圖上，順便把顏色換算回數字。

---

## 操作說明

### 指定地點

輸入框接受三種輸入，按「定位」送出：

| 輸入 | 例子 |
|---|---|
| 地名 | `龍洞` |
| 座標 | `25.11, 121.92` |
| Google Maps 網址 | 貼上完整網址 |

搜尋地名會列出候選讓你挑——同名地點很常見，例如「龍洞」在新北和台東各有一個。
在預報圖範圍外的結果（金門、馬祖）會先濾掉。

Google Maps 的**短網址**（`maps.app.goo.gl/…`）沒辦法在瀏覽器裡展開，
請先點開它，再把跳轉後的完整網址複製回來。

### 讀雨量

定位後，搜尋框下方會顯示目前時距的累積雨量：

> 🟨 6 小時累積 **30～40 毫米** · 資料 12:48 更新

左邊的色塊對應圖上的顏色。數值是**區間**不是精確值——來源是圖片的色階，
只能分辨到色階的分級。結尾的時間是雨量資料的更新時間，
超過 2.5 小時沒更新會轉成黃字提醒。

下方 12 個時距按鈕各自帶一條色條，標出**該地點**在那個時段的雨量，
一眼就看得出哪個時段會下。6 小時與 12 小時兩排共用同一組欄位，
12 小時的按鈕各佔兩格，右緣對齊同一時間點。

### 最愛地點

按搜尋框右邊的 ☆ 把目前地點加入最愛，變成 ★ 代表已收藏，再按一次移除。
最愛會出現在搜尋框下方，點一下直接切換。

上限 5 個。超過時會汰換最舊的那筆，並在狀態列說明移除了哪一個。
**最愛只存在你這台裝置的這個瀏覽器裡**（存在 localStorage），沒有帳號也沒有雲端同步。
手機加的最愛在電腦上看不到，反之亦然；換瀏覽器、用無痕視窗、
或是清掉瀏覽器資料，最愛都會不見。

### 地圖操作

| 動作 | 手機 | 桌機 |
|---|---|---|
| 平移 | 單指拖曳 | 拖曳 |
| 縮放 | 雙指 | 滾輪 |
| 放大到點位／回到全台 | 雙擊 | 雙擊 |
| 回到全台 | 「全台」按鈕 | 「全台」按鈕 |

定位後**不會**自動放大，維持全台視野，圖釘一定看得到。

### 加入主畫面

**iOS Safari**：分享 → 加入主畫面。開啟後是全螢幕、沒有網址列，
圖示是雨滴、名稱「降水點位」（靠 `apple-mobile-web-app-capable`
與 `apple-touch-icon` 達成）。

**Android Chrome**：選單 → 安裝應用程式／加到主畫面。有 `manifest.json`，
所以是真的安裝：獨立視窗、沒有瀏覽器介面、啟動畫面用深色底加雨滴圖示。

manifest 把方向鎖成直向（`"orientation": "portrait"`），因為橫向的地圖只剩約 145px 高，
實際上不好用。

**沒有離線功能**。沒有 service worker，斷網就打不開；
何況預報圖本來就得即時連到氣象署，快取舊圖反而危險。

## 運作方式

沒有後端。整個網站是 GitHub Pages 上的靜態檔。

### 為什麼要預先解析雨量

CWA 的圖沒有 CORS 標頭，畫進 canvas 會 taint，瀏覽器**讀不到像素**。
所以雨量改由排程預先算好：

1. `rain_grid.py` 下載 12 張預報圖，把每個像素的顏色對回色階的 17 個分級
2. 輸出 RLE 壓縮的等級網格（全解析度，每張 gzip 後 9～31 KB）
3. 跟著網站一起部署成**同源**檔案，網頁直接查表

網頁上顯示的圖仍然是即時從 CWA 抓的，只有數值來自網格。

縣市界、海岸線與色塊邊緣的反鋸齒像素不屬於任何色階，
用鄰近像素的多數決補回來（把「無雨」一起納入投票，乾燥區裡的線不會被補成有雨）。
署徽、圖上色階、離島放大框遮住的位置標成「無資料」，不猜。

### 經緯度怎麼對到像素

`calibrate.py` 拿台灣的縣市界 GeoJSON，用 55490 個邊界點去擬合等距圓柱投影的
4 個參數，目標是讓投影後的邊界點盡量落在圖上的黑色線條上。
殘差中位數 1.0 px、平均 2.4 px。參數寫死在 `qpf.js` 的 `PROJ`。

一般不需要重跑，除非 CWA 換了圖的版面。

### 色階與時間文字

右側的色階和上方的發布／有效時間，都是用 CSS `overflow: hidden`
從**同一張圖**裁出來的區塊，不是另外維護的資料。
切換時距時三者必然同步，因為根本是同一個檔案。

## 更新頻率

CWA 約每 6 小時發布一次新的預報。雨量網格由排程每 30 分鐘檢查一次，
發現換版才重新產生並部署，所以網頁上的數值最多落後半小時。

推上 main 也會重新部署。要立刻更新就手動觸發：

```bash
gh workflow run Deploy
```

最快的健康檢查是網頁上雨量那行結尾的更新時間，正常不會超過半小時前。

## 開發

零依賴、零建置步驟。純 ES modules ＋ 純 stdlib Python。

```bash
python3 -m http.server 8777    # 開 http://localhost:8777
```

本機要看雨量數值的話，先產生網格（`rain/` 不進版控）：

```bash
python3 rain_grid.py rain
```

測試（25 項，涵蓋地點解析、投影、雨量網格、最愛）：

```bash
node --test test/*.test.js
```

其中一項會比對 `qpf.js` 與 `rain_grid.py` 的色階定義是否一致——
兩邊若走鐘，讀出來的雨量會全錯。

### 檔案

```
index.html        頁面骨架
app.js            所有 DOM 與互動邏輯
qpf.js            純函式：投影、網址、地點解析、雨量色階、最愛（無 DOM 依賴，測試都打這裡）
style.css         深色主題，手機優先
rain_grid.py      把預報圖解析成雨量等級網格（CI 每次部署都會跑）
calibrate.py      一次性的投影校正，輸出參數與疊合圖供目視確認
make_icon.py      產生 PNG 圖示 180／192／512（macOS 上沒有 Pillow 也沒有 SVG 轉檔工具）
manifest.json     web app manifest，Android 要有它才能真的安裝
.github/workflows/deploy.yml
```

## 已知限制

- **雨量是區間不是精確值**。來源是圖片的色階，只能分辨到分級。
- **數值最多落後 30 分鐘**。CWA 剛發布新一版時，圖已經換了、數值可能還是舊版的。
  狀態列的更新時間就是判斷依據。
- **署徽與圖上色階遮住的位置讀不出來**，會顯示「無法判讀」。
- **最愛不能跨裝置存取**。存在該瀏覽器的 localStorage，手機與電腦各記各的，
  清除瀏覽器資料就會消失。
- **橫向手機很擠**，地圖只剩約 145px 高。建議直向使用。
- 3 小時極短期預報只在颱風／豪雨守視期間發布，本版不做。
